# 팀 개발 규칙

사람을 위한 간단한 협업 규칙입니다. 에이전트 실행 규칙은 루트와 역할별 `AGENTS.md`가 우선합니다.

## 서비스 경계

- Frontend → Backend → VLM 순서를 지킵니다.
- VLM은 이미지 관찰만, Backend는 공개 API와 최종 판단을 담당합니다.
- 계약 변경은 `shared/**` → 제공 서비스 → 소비 서비스 순서로 반영합니다.
- 운영 배포는 AWS Amplify, API Gateway, Lambda, App Runner를 사용합니다.

## 작업 방식

- 기능 브랜치에서 작고 검토 가능한 변경을 만듭니다.
- 다른 역할의 작업이 필요할 때만 `docs/cowork_ground.md`에 요청합니다.
- 비밀값, 개인정보, 실제 자격 증명을 코드·문서·로그에 남기지 않습니다.
- 생성물, 캐시, 가상환경, 모델 가중치, 실제 사진은 Git에 올리지 않습니다.
- API·DB·배포 구조를 바꾸면 영향받는 테스트와 문서를 같은 변경에 포함합니다.

## 커밋과 PR

커밋 제목은 `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:` 중 목적에 맞는 접두사를 사용합니다. 한 커밋에는 가능한 한 하나의 목적만 담습니다.

PR에는 다음을 적습니다.

- 무엇이 달라졌는지
- 계약·환경 변수·배포 영향
- 실행한 테스트와 남은 검증
- 다른 역할이 해야 할 후속 작업

## 완료 기준

- 핵심 성공·실패 경로가 동작합니다.
- 역할별 테스트와 build가 통과합니다.
- shared 계약과 구현이 일치합니다.
- 비밀값과 불필요한 생성물이 포함되지 않습니다.
- 현재 동작과 배포 방법이 역할 문서에 반영됩니다.
