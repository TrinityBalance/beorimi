# 역할 간 요구사항 보드

다른 역할의 작업 없이는 완료할 수 없는 요구사항만 기록합니다. 에이전트는 이 문서를 전체 읽지 않고 자기 역할 카드의 `rg` 명령으로 대상 요청 블록만 조회합니다.

## 요청 제목 형식

```text
### ROLE-NNN [STATUS] → TARGET — 요청 제목
```

- 요청자 접두사: Frontend `FE-`, Backend `BE-`, VLM `VLM-`
- 대상은 Frontend, Backend, VLM 중 하나만 사용합니다. 여러 역할이 필요하면 요청을 역할별로 나눕니다.
- 각 역할은 자기 발신 큐의 가장 큰 번호 다음 번호를 사용하며 번호를 재사용하지 않습니다.
- 제목의 상태가 검색 기준입니다. 상태를 바꿀 때 제목의 `[STATUS]`를 갱신합니다.

## 상태와 소유권

```text
OPEN → ACK → READY → DONE
           ↘ BLOCKED
OPEN 또는 ACK → CANCELLED
```

| 상태 | 의미 | 변경자 |
| --- | --- | --- |
| `OPEN` | 새 요구사항 | 요청자 |
| `ACK` | 범위 확인·처리 시작 | 수신자 |
| `BLOCKED` | 결정·정보·선행 작업 필요 | 수신자 |
| `READY` | 구현·수신자 검증 완료 | 수신자 |
| `DONE` | 연동·완료 조건 확인 | 요청자 |
| `CANCELLED` | 요청 취소 | 요청자 |

- 요청자는 요구사항, 이유·영향, 완료 조건, 관련 계약을 소유합니다.
- 수신자는 응답과 구현·검증 근거를 소유합니다.
- 요청자는 `READY`를 직접 검증한 뒤에만 `DONE`으로 닫습니다.
- API 변경 요청은 관련 `shared/**` 계약 파일을 반드시 적습니다.
- 작업 종료 전 자신이 생성하거나 처리한 요청 ID만 다시 조회해 상태를 갱신합니다.
- 일반 TODO, 비밀키, 자격 증명, 개인정보는 기록하지 않습니다.

## 요청 템플릿

```markdown
### ROLE-NNN [STATUS] → TARGET — 요청 제목

- **우선순위:** `<BLOCKING | HIGH | NORMAL>`
- **필요 시점:** `<통합 전 | 배포 전 | 후속 작업>`
- **요구사항:** 필요한 결과를 한 문장으로 작성
- **이유·영향:** 없으면 막히는 작업
- **완료 조건:** 검증 가능한 조건
- **관련 계약·파일:** `shared/...`, 관련 구현 파일 또는 `없음`
- **수신자 응답:** 미응답
- **구현·검증 근거:** 미완료
```

## 유지 원칙

- 동시 작업자는 자기 발신 큐와 자신에게 배정된 요청 블록만 수정하고 다른 항목을 재정렬하지 않습니다.
- 완료 요청도 추적을 위해 삭제하지 않습니다. 문서가 커질 때만 합의 후 `DONE`·`CANCELLED`를 별도 보관합니다.
- 확정된 명세는 이 보드가 아니라 `shared/` 계약과 역할별 가이드에 반영합니다.
