# 역할 간 요구사항 보드

Frontend, Backend, VLM 작업자가 다른 역할에 필요한 요구사항과 응답을 한곳에서 추적하는 협업 보드입니다. 각 역할 내부의 일반 TODO나 개인 메모는 해당 작업 가이드·이슈에서 관리하고, **다른 역할의 작업 없이는 완료할 수 없는 요구사항만** 이 문서에 기록합니다.

## 작업 시작 시 확인

모든 작업자는 자기 역할 가이드와 함께 이 문서를 읽고, 자신을 대상으로 한 `OPEN`, `ACK`, `BLOCKED`, `READY` 요청을 확인합니다.

```powershell
rg -n "\*\*상태:\*\* (OPEN|ACK|BLOCKED|READY)" docs/cowork_ground.md
```

자신의 작업이 다른 역할의 미완료 요청에 의존하면 추측으로 구현하지 말고 해당 요청에 응답하거나 새 요청을 작성합니다.

## 요청 번호

| 요청 역할 | 접두사 | 예시 |
| --- | --- | --- |
| Frontend | `FE-` | `FE-001` |
| Backend | `BE-` | `BE-001` |
| VLM | `VLM-` | `VLM-001` |

- 요청자는 자기 역할 큐에서 가장 큰 번호 다음 번호를 사용합니다.
- 번호는 삭제하거나 재사용하지 않습니다.
- 여러 역할을 대상으로 해도 요청자 역할의 접두사를 사용합니다.
- 한 요청에는 하나의 검증 가능한 결과만 요구합니다. 결과가 독립적이면 요청을 나눕니다.

## 상태 흐름

```text
OPEN → ACK → READY → DONE
           ↘ BLOCKED
OPEN 또는 ACK → CANCELLED
```

| 상태 | 의미 | 상태를 바꾸는 역할 |
| --- | --- | --- |
| `OPEN` | 요청자가 새 요구사항을 등록함 | 요청자 |
| `ACK` | 수신자가 요구사항을 확인하고 작업 범위를 이해함 | 수신자 |
| `BLOCKED` | 수신자가 구현할 수 없으며 결정·정보·선행 작업이 필요함 | 수신자 |
| `READY` | 수신자 구현과 자기 영역 검증이 끝나 요청자 확인을 기다림 | 수신자 |
| `DONE` | 요청자가 연동 결과와 완료 조건을 확인함 | 요청자 |
| `CANCELLED` | 더 이상 필요하지 않으며 취소 이유를 남김 | 요청자 |

## 필드 소유권

- **요청자:** 제목, 대상, 우선순위, 요구사항, 이유·영향, 완료 조건, 관련 계약·파일을 작성합니다.
- **수신자:** 상태를 `ACK`, `BLOCKED`, `READY`로 바꾸고 수신자 응답과 구현·검증 근거를 작성합니다.
- **요청자:** `READY` 결과를 직접 확인한 뒤 `DONE`으로 닫습니다. 실패하면 상태를 `OPEN`으로 되돌리고 부족한 조건을 구체적으로 추가합니다.
- 요구사항의 의미가 바뀌면 기존 요청을 몰래 고치지 말고 변경 이유를 응답에 기록합니다. 결과가 크게 달라지면 새 번호를 만듭니다.

## 요청 작성 규칙

1. 다른 역할의 작업이 필요한 것을 발견하면 코드 우회 구현 전에 요청을 등록합니다.
2. API 요청·응답 변경이면 `shared/` 계약 파일을 관련 파일에 반드시 적습니다.
3. `BLOCKING` 요청은 현재 작업을 실제로 막는 경우에만 사용합니다.
4. 수신자는 자기 역할 가이드를 따라 구현하고 검증 명령과 결과를 근거에 남깁니다.
5. 작업 종료 전 자신이 생성하거나 처리한 요청의 상태를 최신으로 갱신합니다.
6. 동시에 편집할 때는 자기 역할 큐와 자신이 처리 중인 요청 블록만 수정하고 다른 기록을 재정렬하지 않습니다.
7. 비밀키, 토큰, 개인정보, 실제 운영 자격 증명은 기록하지 않습니다.

## 요청 템플릿

아래 형식을 복사해 요청자 역할의 발신 큐 맨 아래에 추가합니다.

```markdown
### ROLE-NNN — 요청 제목

- **요청자:** `<Frontend | Backend | VLM>`
- **대상:** `<Frontend | Backend | VLM | 여러 역할>`
- **상태:** `<OPEN>`
- **우선순위:** `<BLOCKING | HIGH | NORMAL>`
- **필요 시점:** `<통합 전 | 배포 전 | 후속 작업>`
- **요구사항:** 필요한 결과를 한 문장으로 작성
- **이유·영향:** 이 결과가 없을 때 막히는 작업
- **완료 조건:** 수신자가 충족해야 하는 검증 가능한 조건
- **관련 계약·파일:** `shared/...`, 관련 구현 파일 또는 `없음`
- **수신자 응답:** 미응답
- **구현·검증 근거:** 미완료
```

## 보드 유지 원칙

- 완료된 요청도 번호와 근거 추적을 위해 삭제하지 않습니다.
- 파일이 길어지면 모든 역할이 합의한 별도 보관 문서로 `DONE`·`CANCELLED` 요청만 이동합니다.
- 이 문서는 구현 명세의 원본을 대신하지 않습니다. 확정된 API·스키마는 `shared/`에, 영역별 구현 규칙은 각 역할 가이드에 반영합니다.
- 코드와 문서가 요청 내용보다 최신이면 코드·계약을 확인해 요청을 갱신하고, 오래된 요청을 그대로 구현하지 않습니다.
