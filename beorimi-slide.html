B2
비동기 설계

결과를 기다리는 대신 상태를 기록합니다

queued→ processing→ completed ↘ failed
같은 사진을 두 번 분석하지 않습니다 아직 queued(대기)인 작업만 골라 processing(처리 중)으로 변경 · 이미 누가 가져갔으면 그냥 종료
세 번까지 다시 시도합니다 실패하면 대기 상태로 되돌림 · 세 번째 실패에서 failed로 확정하고 사유 기록
호출이 실패해도 작업을 놓치지 않습니다 DB가 처리기를 부르는 호출이 실패할 수 있음 · 1분마다 도는 예약 작업이 가장 오래 밀린 것부터 대신 처리
사진은 30일까지만 두고 지웁니다 매일 새벽 정리 작업이 만료된 기록과 원본 사진을 함께 삭제
범위는 강남구로 고정했습니다 자치구 컬럼 없음 · 강남구 전용 스코프

VLM이란?
사진을 구조화된 관찰 데이터로 바꾼다

사진을 이해하고, 물체의 종류·재질·상태·위치를 정해진 형식으로 설명한다.

INPUT
폐기하려는 물품 사진
⇢gpt-5.6-sol
OpenAI Responses API
프롬프트 + JSON Schema
OUTPUT
구조화된 관찰 JSON
이 프로젝트의 기본 모델 gpt-5.6-sol · OpenAI Responses API 사용 · 프롬프트 + JSON Schema 기반 제어 · 환경변수로 모델 변경 가능
Beorimi에서 VLM의 자리 사진만 보고 최종 답을 내리는 심판이 아니라, 백엔드가 판단할 수 있는 관찰 근거를 만드는 눈이다.
V2
운영 흐름 · 관찰 → 계약 검증 → 보안 검증

이 프로젝트에서 VLM은 사진을
안전한 관찰 데이터로 변환한다

운영 경로에서는 사진 데이터를 받아 분석하고, 엄격한 계약과 보안 검사를 통과한 결과만 전달한다.

01
사진 입력
업로드된 사진 데이터를 받아 이미지 속 물체를 원본 상세도로 확인한다.
02
물체 관찰
사진 속 폐기물 후보를 찾고 품목명, 재질, 상태, 크기와 위치를 관찰한다.
03
JSON 구조화
Structured Outputs를 사용해 결과가 정해진 JSON Schema를 따르도록 제한한다.
04
보안 검증
사진 속 명령문을 신뢰하지 않고 Prompt Injection 신호가 있으면 결과를 차단한다.

주요 출력

품목명카테고리재질 개수예상 크기상태 신뢰도확인 질문bbox
V3
설계 원칙 · 모델 관찰과 서비스 판단의 분리

VLM은 관찰하고, 서비스 로직은
최종 폐기 방법을 결정한다

역할을 분리해 모델의 불확실한 추측이 곧바로 수수료나 폐기 안내가 되는 것을 막는다.

VLM이 하는 일
  • 사진 속 물품 후보와 개수 찾기
  • 품목·카테고리·재질·상태 관찰하기
  • 크기, 신뢰도, bbox와 확인 질문 반환하기
  • 사진 품질과 Prompt Injection 위험 신호 표현하기
VLM이 하지 않는 일
  • 배출 가능 여부를 최종 결정하지 않는다
  • 수수료를 추측하거나 계산하지 않는다
  • 재활용·대형폐기물 분류를 확정하지 않는다
  • 신고 필요 여부와 최종 배출 방법을 안내하지 않는다
VLM 결과 이후, 별도의 카탈로그와 규칙 기반 코드가 수수료·분류·배출 방법을 결정한다.
