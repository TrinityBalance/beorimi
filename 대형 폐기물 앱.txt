## 1. 데이터 확보 (팩트)

- 공공데이터포털에 전국대형폐기물수거수수료정보 표준데이터가 있고, 그 안에 "서울특별시_강남구_대형폐기물수거수수료정보" 파일데이터가 포함됨. 파일 + Open API 둘 다 있음.
- 표준데이터라 컬럼은 그룹(분류) / 폐기물명 / 규격 / 수수료 구조 (세종 사례 기준, 강남도 동일 규격일 것으로 추론).
- 원 근거는 강남구 폐기물 관리조례 제8조 별표, 수거는 대행업체(태화용역).
- 핵심 포인트 하나: "위에 열거되지 아니한 품목은 유사한 품목 수수료에 준함" ← 이 문구가 **유사도 기반 추론의 공식 근거**가 됨. 데모 셀링포인트로 쓰기 좋음.
- 무상수거 분기(폐가전 무상방문수거) 별도 존재 → 냉장고·세탁기·에어컨 등은 무상수거 대상 우선 확인.

→ **데이터는 CSV 한 방이면 끝남. 크롤링 불필요. 여기서 시간 안 씀.**

## 3. 직언 두 개

**(1) 크기 판독이 진짜 리스크임**

단안 사진에서 절대 치수 추정 = 기준물체 없으면 원리적으로 불가. 근데 수수료 테이블은 규격(1m 미만/이상)에서 금액이 갈림 → 여기가 정확도 다 깎아먹음.

권장 우회 (셋 중 택1~2):
- VLM에 **규격 버킷만** 물어봄 (소/중/대) + confidence 낮으면 유저 확인 UI 띄움
- 기준물체 유도 ("A4·담뱃갑·스마트폰 같이 찍어주세요")
- 결과 화면에 규격 셀렉터 노출 → **오답을 UX로 흡수**

의견: 마지막 방법이 해커톤 ROI 최고. "AI가 후보를 좁히고 사람이 1초 확정"이 심사에서도 안 까임.

**(2) GraphRAG 오버킬**

- 수수료 데이터는 사실상 flat table임. 그래프 이득이 거의 없음.
- MS GraphRAG 정식 파이프라인(엔티티 추출 → 커뮤니티 탐지 → 요약)은 인덱싱만 수시간 + 토큰 폭탄 + 튜닝 필요. 2일에 넣으면 다른 게 다 죽음.

**대신 "경량 지식그래프"로 가기 ㄱ**

```
(품목) -[분류]-> (그룹)
(품목) -[규격]-> (규격노드) -[수수료]-> (금액)
(품목) -[유사]-> (품목)        # 임베딩 top-k, 미등재 대응
(품목) -[예외]-> (무상수거 / 재활용 / 종량제 / 불연성마대)
(규정)   조례 8조 별표 근거 링크
```

networkx or SQLite + 임베딩. 구축 3~4시간. 2~3홉 탐색으로 "왜 이 금액인지" 경로 설명 가능 → **설명가능성이 그래프 쓰는 유일한 정당화**. 그거 하나로 밀면 됨.

Neo4j 띄우는 건 비추 (환경 세팅에서 시간 샘).
